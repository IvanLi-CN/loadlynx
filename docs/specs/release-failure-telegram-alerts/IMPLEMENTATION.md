# Implementation

## Status

- Current status: 已更新

## Implementation Summary

- `notify-release-failure.yml` watches only the unified `Release (LoadLynx)` workflow on `main`.
- Both jobs call Oidrune `notify.yml` at trusted commit `e48822f99c6402a753ed86557ea029754cbab20b` (release `v0.1.14`).
- The caller grants `id-token: write`, relies on Oidrune's default gateway, and passes no Telegram secret or gateway override.
- Failure and smoke summaries are fully generated by LoadLynx and include project, status/result, target SHA, run URL, and the matching failure/smoke title.
- Release failure notifications stay scoped to release workflow failures; ordinary PR CI failures remain GitHub check feedback only.
- The release workflow summary and release intent snapshot carry PR label release context for failure investigation.

## Remaining Gaps

- Telegram smoke remains available through the workflow's manual dispatch path; it was intentionally not dispatched during validation.

## Verification

- `.github/scripts/notify-release-failure-contract.test.mjs` verifies the pinned reusable workflow, top-level OIDC permission, preserved triggers and failure conditions, absence of legacy secret/override inputs, and complete failure/smoke summaries.
- `Code Check` runs the notifier contract test through `npm run test:release-failure-notifier`.
